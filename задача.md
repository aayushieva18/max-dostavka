# Задача — mini app «Доставка» для MAX

Записано со слов пользователя 2026-09-14, обновлено 2026-09-15 (переход с VK
на MAX). Это единственный источник правды о том, что должно получиться. Если
пользователь позже что-то уточнит или поменяет — правь этот файл, а не держи
изменения только в переписке.

## История: почему MAX, а не VK

Изначально собирали мини-приложение для ВКонтакте (так и назывался проект).
2026-09-15 пользователь спросила про мини-приложение в мессенджере MAX;
после проверки выяснилось, что это отдельная от VK платформа со своим
способом подключения. Пользователь решила: **полностью перейти на MAX**,
версия для VK больше не нужна. Весь код и все документы проекта переписаны
под MAX (папка проекта тоже переименована: `vk-доставка` → `max-доставка`).

## Кто пользуется приложением

Два разных человека, два разных экрана:

1. **Покупатель** — обычный человек в MAX, который хочет заказать продукт
   с доставкой на свой адрес.
2. **Хозяйка (она же курьер)** — сама пользователь. Развозит заказы, видит их на
   карте, отмечает, что развезла.

## Экран покупателя

- Открывает окно заказа внутри мини-приложения.
- Форма заказа: имя, адрес, телефон, список продуктов с количеством (кнопки «+»/«−»
  на каждый продукт), кнопка «Заказать».
- **Важно:** если покупатель уже заказывал раньше, при следующем заказе его имя,
  адрес и телефон должны быть уже заполнены (не вводить заново, не слетать).
- Нельзя заказать продукт, если он уже закончился (см. остатки ниже) — товар,
  которого нет в наличии, недоступен для выбора.
- Видит карту, на которой отмечено, где сейчас едет курьер (хозяйка) — чтобы,
  если курьер проезжает мимо, можно было позвонить и забрать заказ самому.
- Видит примерное время прибытия курьера к своей точке.
- Кнопка «Заказ забрал» — покупатель нажимает, когда получил заказ.

## Экран хозяйки (курьера)

- Заводит товары сама (название + сколько есть в наличии), может переименовать
  существующий товар.
- Перед выездом обновляет, сколько товара доступно к заказу. Когда доступное
  количество разбирают по заказам — товар становится недоступен для новых
  заказов у покупателей.
- Видит карту со всеми точками заказов на сегодня.
- Клик по точке на карте (или по строке в списке) показывает: имя, телефон,
  адрес, что и сколько заказано.
- Приложение прокладывает маршрут по всем точкам и показывает время прибытия
  к каждой (чтобы покупатели не звонили и не спрашивали «когда приедете»).
- Кнопка «Заказ выдал» — хозяйка нажимает, когда отдала заказ.

## Карта

- Используем Яндекс Карты (карта, точки, геокодирование адреса, построение
  маршрута, расчёт времени в пути) — это решение не связано с переходом VK→MAX,
  осталось прежним.
- Поиск адреса жёстко ограничен Забайкальским краем (Чита, Агинский округ и
  весь остальной край) — адрес из другого региона не найдётся специально.
- Ключ Яндекса пользователь оформила сама, уже вписан в код.

## MAX-специфика

- Определение покупателя/хозяйки — через `window.WebApp.initDataUnsafe.user.id`
  (мост MAX, подключается тегом `<script>`, без сложной настройки).
- Мини-приложение MAX **обязательно привязывается к боту** в MAX — само по
  себе открыться не может. Это отдельный шаг регистрации перед публикацией
  (см. `сборка.md`).
- Хранилище MAX (`DeviceStorage`) — резервная копия данных покупателя на
  случай недоступности сервера (аналог того, что раньше делал VK Storage).

## Точно нельзя без разрешения пользователя

- Самостоятельно публиковать приложение / регистрировать бота в MAX.
- Трогать аккаунт пользователя в MAX.
- Отправлять код или данные куда-либо наружу.
- Устанавливать программы/пакеты на компьютер без явного «да» на конкретную установку.

## Критерий «готово»

Приложение готово к тому, чтобы отправить его на публикацию в MAX (пользователь
публикует сама — агент только доводит код до этого состояния).
